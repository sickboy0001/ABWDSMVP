サーバー（Hono/Turso）とクライアント（ブラウザ）がどのように役割を分担し、連携して動くのかの**全体処理フロー**と**アーキテクチャ設計図**です。

---

## 1. システム全体構成図

```
+-----------------------------------------------------------------------------------+
| 【ブラウザ（クライアント側）】                                                     |
|                                                                                   |
|  [画面 (HTML)] ──(1.設定入力/保存)──> [htmx]                                      |
|       ▲                                 │                                         |
|       │                                (HTTP POST)                                |
|  (4.描画: 60fps)                        ▼                                         |
|       │                    【サーバー (Hono / Cloudflare or Netlify)】            |
|  [HTML5 Canvas]                         │                                         |
|       ▲                            (2.認証・保存)                                 |
|       │                                 ▼                                         |
|  [シミュレーションエンジン] <──(3.シード値 & 設定JSON返却)─── [Turso DB]          |
|  (Web Worker / TypeScript)                                                        |
|  ※5万人の計算を完全ブラウザ処理                                                   |
+-----------------------------------------------------------------------------------+

```

---

## 2. 処理フロー（ステップ・バイ・ステップ）

シミュレーションが実行され、結果が保存されるまでの流れは大きく4ステップに分かれます。

### Step 1: 画面読み込み・シナリオ取得（Hono → ブラウザ）

1. ユーザーがWebページ（`/scenarios/123`）にアクセスします。
2. **Hono** が Turso からシナリオ設定（エージェント数: 10,000、税率: 10%、**シード値: 9823741** など）を取得します。
3. **Hono** は画面のHTMLフレームと、`data-config='{"seed": 9823741, "agents": 10000, ...}'` のような設定データを埋め込んで返します。

### Step 2: ブラウザ上での爆速シミュレーション実行（完全ローカル処理）

1. **ブラウザ**（JavaScript）が埋め込まれた設定データを受け取り、内部のシミュレーションエンジンを初期化します。
2. ユーザーが「再生（PLAY）」ボタンを押すと、ブラウザ内部で1ターンずつシミュレーション計算を開始します。
3. **描画処理**: 毎ターンの計算結果（ジニ係数やヒストグラム用データ）を、**HTML5 Canvas** や Chart.js を使って 60fps で滑らかに描画します。
* **メリット**: 画面の更新に通信（ネットワーク遅延）が一切挟まらないため、超高速でアニメーションが動きます。



### Step 3: 途中介入（htmx ↔ Hono）

1. ユーザーがシミュレーション実行中に「基本所得（UBI）をONにする」などの政策介入を行います。
2. **htmx** が `hx-post="/api/log-event"` で Hono サーバーへ「Turn 100でUBI発動」という操作イベントログを非同期送信します（Tursoへ保存）。
3. 同時に、**ブラウザ側のシミュレーションエンジン**の実行フラグも即座に切り替わり、計算ルールが動的に変更されます。

### Step 4: 結果ログの永続化・共有（ブラウザ → Hono → Turso）

1. シミュレーションが完了（例: 1,000ターン到達）すると、ブラウザは最終結果のサマリー（最終ジニ係数、生存率、ターンごとの指標配列）を生成します。
2. **htmx / fetch API** で Hono へ計算サマリーを送信し、**Turso DB** に実行結果として保存します。
3. 以降、他のユーザーが同じシナリオを開いた場合は、保存された「シード値」を使ってブラウザ上で100%同じシミュレーションが即座に再現されます。

---

## 3. 画面を固めない工夫（Web Workerの活用）

ブラウザで5万人の計算を回すと、通常はJavaScriptの処理が重くなり画面（UI）がフリーズします。これを防ぐために **Web Worker** を使用します。

```
[メインスレッド (画面側)]               [Web Worker (裏方の計算用)]
        │                                       │
        ├── (1) パラメータ & シード値送信 ─────>│
        │                                       ├── 5万人のマッチング判定
        │                                       ├── 資産移動・税金計算
        │                                       ├── ジニ係数算出
        │<── (2) 集計結果データ (毎ターン) ─────┤
        │                                       │
  [Canvas描画]
  (UIはサクサク動く)

```

* **メインスレッド**: ボタン操作の受け付け、htmx通信、Canvasへの描画を担当（描画専用）。
* **Web Worker**: バックグラウンドで5万人のシミュレーション計算のみをひたすら実行（計算専用）。

---

## 4. この設計のメリット

* **サーバーインフラ費用がほぼタダ**: サーバーはHTMLの受け渡しと数KBのJSONデータ保存しかしないため、無料枠（Cloudflare / Netlify + Turso）で大量のアクセスに耐えられます。
* **圧倒的なUI体感速度**: サーバーとの通信を待たずにブラウザのCPUで直接描画するため、ぬるぬる動くリサーチダッシュボードが実現します。
* **再現性の保持**: 「設定パラメータ＋シード値」さえデータベースに保存しておけば、サーバー側に重い計算結果ログをすべて保存する必要がありません。
